ENCODINGS AND FORMAT LIMITS
- All GDI/NOD controls resolved. GDI only=F9,NOD only=FA,neither=FF,both=FB. These are patched executable bytes, NOT native ownership bitmasks.
- Weapon choice25(None) writesFF; other choices write their index.
- Armour writes selected index+1. UI names are only Level1..Level5; native names should come from engine enums, not assumed labels.
- Building construction choices None/Infantry/Vehicles/Helicopters/Structures write0/2/4/6/8.
- Aircraft Landable checkbox is inverted:checked0,unchecked1. Other booleans write checked1/unchecked0.
- Most numeric fields are one byte; cost/health and a few building values use signed16-bit depending on object. Those widths follow instruction immediates in the old EXE, not sensible universal game limits.
- Vehicles:dinosaurs(index16..19) cost writes1 byte; others2. HP writes1 byte for indices2,6,7,8,14; others2.
- Naval:cost andHP2 bytes.
- Aircraft:cost2 bytes,HP1 byte even though form allows30000; old inconsistency not to reproduce.
- Infantry:minigunner(index0) cost1 byte; other cost2. HP1 byte.

OPEN/BACKUP/RESET
Open450c34 checks existence of c&c95.exe and default.dat. On first open it copies the full EXE to default.dat in2048-byte chunks; later opens reuse that backup. No version/hash/header/size validation is visible in this handler. Default All453c28 asks confirmation then rewrites the entire EXE from default.dat. Thus default means the first backed-up executable, potentially already modified, rather than canonical factory values. Preserve this familiar reset concept in native app using immutable compiled defaults and named presets, not binary backup replacement.

LEGACY LIMITATIONS / BUGS TO AVOID
- Aircraft Tech Level omitted; form explicitly says its offset was unknown.
- Technicians and civilian buildings omitted.
- Wall choices pass zero for unknown offsets. Load disables many controls but still reads offset0; decimal77 is consistent with'M' in an MZ header. Save continues to seek/write those zero offsets instead of guarding them. The native implementation must never reproduce this.
- Making naval craft buildable is warned against in the original UI because their mission behavior is specialized.
- Changes are explicitly saved per selected object; changing selection reloads fields, so unsaved edits are lost.

NATIVE INTEGRATION RECOMMENDATION
Use the existing Workshop as a CnCGEdit-inspired rules editor, backed by native type definitions and existing per-preset persistence. Keep original compiled values as Stock, offer named custom presets, clear Save/Reset and restart requirement, and preserve the single-player multiplayer lockout.
Use proper boolean switches and named enum pickers rather than numeric IDs. Separate ownership(GDI/NOD) from human-player-only cheats:changing a shared unit type also changes enemy units of that type. Keep runtime cheats in a separate section.
Add field-specific safety checks around engine capacities and lifecycle invariants. A carrier flag should not imply payload support or passenger capacity without verifying engine behavior. Constructor cross-check now confirms CnCGEdit Landable modifies the inverse fixed-wing argument; native IsLandable is a separate flag. Keep them separate, and omit the misleading legacy label until actual landing behavior is tested.
No Windows executable patching or bundled CnCGEdit binary is needed in the iOS app. Data tables and native source provide a cleaner integration than embedding/emulating this editor.
